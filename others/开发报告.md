# 多模态科学文献智能解析与知识图谱构建平台

**Research on Multi-modal Scientific Literature Intelligent Parsing and Knowledge Graph Construction Platform**

---

## 摘要

随着科学文献数量的爆发式增长，传统的人工阅读和标注方式已无法满足科研人员对文献深度理解的需求。本文设计并实现了一个多模态科学文献智能解析与知识图谱构建平台，该平台采用前后端分离架构，前端基于React和TypeScript构建，后端基于FastAPI构建，结合Celery异步任务队列、MySQL关系数据库和Neo4j图数据库，实现了从科学文献PDF解析到知识图谱构建的全流程解决方案。平台支持PDF文档上传、异步解析、实体关系抽取、知识图谱可视化和基于GraphRAG的智能问答功能。实验表明，该平台能够有效提升科学文献处理效率，为科研人员提供便捷的文献理解和知识发现工具。

**关键词**：科学文献解析；知识图谱；信息抽取；GraphRAG；FastAPI；Neo4j

---

## Abstract

With the explosive growth of scientific literature, traditional manual reading and annotation methods can no longer meet the needs of researchers for deep understanding of documents. This paper designs and implements a multi-modal scientific literature intelligent parsing and knowledge graph construction platform. The platform adopts a front-end and back-end separation architecture, with the front-end built on React and TypeScript, and the back-end built on FastAPI, combined with Celery asynchronous task queue, MySQL relational database, and Neo4j graph database. It implements a full-process solution from scientific literature PDF parsing to knowledge graph construction. The platform supports PDF document upload, asynchronous parsing, entity-relation extraction, knowledge graph visualization, and GraphRAG-based intelligent question answering. Experiments show that this platform can effectively improve the efficiency of scientific literature processing and provide researchers with convenient tools for document understanding and knowledge discovery.

**Keywords**: Scientific Literature Parsing; Knowledge Graph; Information Extraction; GraphRAG; FastAPI; Neo4j

## 1 引言

### 1.1 研究背景

科学文献是知识传播和学术交流的重要载体。据统计，全球每年发表的科研论文数量已超过300万篇，其中材料科学、化学、物理等领域的文献增长尤为迅速。面对海量的文献资源，科研人员面临着"信息过载"的困境：如何在有限的时间内从大量文献中快速提取有价值的信息，成为制约科研效率的关键瓶颈。

传统的文献处理方式主要依赖人工阅读和标注，存在以下问题：

（1）**效率低下**：一篇完整的学术论文阅读时间通常需要数小时，对于需要进行系统性文献调研的研究者而言，这一过程耗时巨大。

（2）**信息遗漏**：人工阅读容易忽略文档中的关键信息，尤其是表格、公式、图表等非文本元素中蕴含的知识。

（3）**知识孤岛**：不同文献中的相关知识难以建立关联，无法形成系统性的知识网络。

（4）**难以复用**：文献中的实体、关系等知识难以结构化存储和检索，限制了知识的复用和发现。

### 1.2 研究意义

针对上述问题，研究人员尝试引入人工智能技术来提升文献处理的自动化程度。近年来，自然语言处理（NLP）、计算机视觉（CV）和知识图谱（KG）技术的快速发展，为科学文献智能处理提供了新的技术途径。

（1）**多模态理解**：现代深度学习模型能够同时处理文本、图像、表格等多种模态信息，为科学文献的全面解析提供了可能。

（2）**知识抽取**：命名实体识别（NER）、关系抽取（RE）等技术可以从文本中自动提取结构化知识。

（3）**知识图谱**：图数据库技术为知识的组织和关联提供了高效的存储和查询机制。

（4）**智能问答**：检索增强生成（RAG）技术结合大语言模型（LLM），能够实现基于知识图谱的智能问答。

### 1.3 本文贡献

本文的主要贡献包括：

（1）设计并实现了一个完整的多模态科学文献智能解析与知识图谱构建平台，该平台采用微服务架构，支持大规模文档的并行处理。

（2）提出了基于Celery的任务队列设计方案，实现了PDF解析、实体抽取、图谱构建等任务的异步执行，支持任务的暂停、恢复、终止和重试。

（3）构建了基于Neo4j和Qwen的GraphRAG问答系统，实现了从关键词提取、图谱检索到LLM生成的完整问答流程。

（4）开发了友好的人机协同标注界面，支持双栏对比视图、多级审核流程和版本管理，提升了标注效率和标注质量。

本文后续内容组织如下：第2节介绍相关技术与背景；第3节阐述系统总体设计；第4节描述系统的详细设计与实现；第5节展示系统部署与测试结果；第6节总结全文并展望未来工作。

## 2 相关技术与背景

### 2.1 科学文献解析技术

科学文献解析是将PDF格式的原始文档转换为结构化数据的过程，是整个系统的数据入口。相关技术包括：

#### 2.1.1 PDF文本提取

PDF（Portable Document Format）是学术论文最常用的发布格式。PDF解析的主要技术包括：

- **PyMuPDF**（原名fitz）：基于MuPDF引擎的Python绑定，提供高效的文本提取功能，支持页面渲染、文本搜索、注解提取等操作。

- **PDFPlumber**：专注于表格提取的Python库，能够识别PDF中的表格结构，提取行列数据和合并单元格信息。

- **PDF.js**：Mozilla开发的JavaScript PDF渲染引擎，支持在浏览器中渲染PDF页面，提供文本选择和复制功能。

#### 2.1.2 版面分析

版面分析旨在识别PDF页面中的不同区域，如标题、段落、表格、图表、公式等。主流方法包括：

- **基于规则的方法**：利用PDF的内部结构信息（如字体大小、位置等）进行区域分类。

- **基于深度学习的方法**：如LayoutLMv3（微软研究院提出），结合文本、图像和布局信息进行端到端的版面分析。

#### 2.1.3 OCR识别

对于扫描版PDF或包含图片文字的页面，需要使用OCR（光学字符识别）技术。主流工具包括：

- **Tesseract OCR**：Google开源的OCR引擎，支持多语言识别。

- **PaddleOCR**：百度开源的OCR工具，对中文识别效果较好。

### 2.2 信息抽取技术

信息抽取是从解析后的文本中提取结构化知识的过程，主要包括：

#### 2.2.1 命名实体识别（NER）

NER旨在识别文本中的实体及其类型。常用方法包括：

- **BiLSTM-CRF**：经典的序列标注模型，结合双向LSTM和CRF层。

- **预训练语言模型**：如BERT、RoBERTa、SciBERT等，通过微调进行NER任务。

SciBERT是专门针对科学文本预训练的BERT变体，在科学文献NER任务上表现优异。

#### 2.2.2 关系抽取（RE）

关系抽取旨在识别实体之间的关系。常用方法包括：

- **管道方法**：先识别实体，再判断实体对之间的关系。

- **联合抽取方法**：同时进行实体识别和关系抽取，如CASREL、PRGC等模型。

- **基于LLM的方法**：利用大语言模型的零样本或少样本能力进行关系抽取。

### 2.3 知识图谱技术

#### 2.3.1 图数据库

图数据库以图结构存储数据，适合处理复杂的关系网络。主流图数据库包括：

- **Neo4j**：最流行的图数据库之一，使用Cypher查询语言，提供完善的生态工具。

- **Nebula Graph**：国产分布式图数据库，支持超大规模图谱。

- **JanusGraph**：基于Apache TinkerPop的分布式图数据库。

#### 2.3.2 Neo4j图数据库

Neo4j是本文采用的图数据库，其核心概念包括：

（1）**节点（Node）**：表示实体，具有标签（Label）和属性（Property）。

（2）**关系（Relationship）**：表示实体间的联系，具有类型（Type）和属性。

（3）**Cypher**：Neo4j的声明式查询语言，支持模式匹配、路径查询等操作。

本文设计的图谱节点类型包括：Material（材料）、Property（性能）、Method（方法）、Parameter（参数）、Document（文档）、Result（结果）。

### 2.4 检索增强生成技术（RAG）

#### 2.4.1 RAG架构

RAG（Retrieval-Augmented Generation）将检索系统和生成模型相结合，提高LLM的准确性和可信度。典型架构包括：

```
用户查询 → 检索系统 → 相关文档 → 上下文组装 → LLM生成 → 答案输出
```

#### 2.4.2 GraphRAG

GraphRAG是RAG的扩展，利用知识图谱替代向量数据库作为检索源。其优势包括：

（1）**结构化知识**：图谱中的实体和关系提供了明确的语义结构。

（2）**多跳推理**：支持基于路径的复杂推理查询。

（3）**可解释性**：检索结果可以直接追溯到图谱中的实体和关系。

### 2.5 大语言模型（LLM）

#### 2.5.1 主流LLM

- **Qwen**（通义千问）：阿里巴巴推出的多语言大模型，支持中英文，在中文科学文本理解上表现优异。

- **LLaMA**（Large Language Model Meta AI）：Meta开源的大语言模型，生态丰富。

- **ChatGLM**：智谱AI推出的中英文双语模型，适合中文场景。

#### 2.5.2 LM Studio

LM Studio是本地LLM部署工具，支持多种模型格式，提供OpenAI兼容的API接口，便于集成到现有系统中。

### 2.6 异步任务处理技术

#### 2.6.1 Celery

Celery是Python生态中最流行的分布式任务队列，支持：

- **异步执行**：将耗时任务放入队列异步执行，提高系统响应速度。

- **任务调度**：支持定时任务和周期性任务。

- **任务监控**：提供Flower监控界面，实时查看任务状态。

- **任务控制**：支持任务的暂停、恢复、终止和重试。

### 2.7 本章小结

本章介绍了与本系统相关的关键技术，包括科学文献解析技术、信息抽取技术、知识图谱技术、RAG技术和异步任务处理技术，为后续系统设计奠定了技术基础。

### 4.1 后端系统实现

#### 4.1.1 项目结构

后端项目采用模块化结构，便于维护和扩展：

```
backend/
├── app/
│   ├── api/v1/                     # API 路由（15 个模块）
│   │   ├── __init__.py
│   │   ├── router.py               # 路由聚合
│   │   ├── auth.py                 # 认证
│   │   ├── users.py                # 用户管理
│   │   ├── permissions.py          # 权限管理
│   │   ├── documents.py            # 文档管理
```

```python
from datetime import datetime, timedelta
from jose import JWTError, jwt
from passlib.context import CryptContext
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/v1/auth/login")

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)

def get_password_hash(password: str) -> str:
    return pwd_context.hash(password)

def create_access_token(data: dict, expires_delta: Optional[timedelta] = None) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + (expires_delta or timedelta(minutes=30))
    to_encode.update({"exp": expire, "type": "access"})
    return jwt.encode(to_encode, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM)

def create_refresh_token(data: dict) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(days=7)
    to_encode.update({"exp": expire, "type": "refresh"})
    return jwt.encode(to_encode, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM)
```

```python
class ParsingService:
    def extract_text_with_pymupdf(self, file_path: str) -> Dict:
        """使用PyMuPDF提取文本和元数据"""
        doc = fitz.open(file_path)
        result = {
            "metadata": {
                "title": doc.metadata.get("title", ""),
                "author": doc.metadata.get("author", ""),
                "page_count": len(doc)
            },
            "pages": []
        }
        for page_num in range(len(doc)):
            page = doc[page_num]
            result["pages"].append({
                "page_number": page_num + 1,
                "text": page.get_text(),
                "width": page.rect.width,
                "height": page.rect.height
            })
        doc.close()
        return result
    
    def extract_tables_with_pdfplumber(self, file_path: str) -> List[Dict]:
        """使用PDFPlumber提取表格"""
        tables = []
        with pdfplumber.open(file_path) as pdf:
            for page_num, page in enumerate(pdf.pages):
                for table in page.extract_tables():
                    tables.append({
                        "page_number": page_num + 1,
                        "data": table
                    })
        return tables
```

系统使用axios进行HTTP请求封装，实现Token自动管理和错误处理：

```typescript
import axios, { AxiosError, AxiosRequestConfig } from "axios";
import { message } from "antd";

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || "/api/v1",
  timeout: 30000,
  headers: {
    "Content-Type": "application/json",
  },
});

// 请求拦截器 - 添加Token
api.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem("access_token");
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// 响应拦截器 - 处理401和Token刷新
api.interceptors.response.use(
  (response) => response.data,
  async (error: AxiosError) => {
    const originalRequest = error.config as AxiosRequestConfig & { _retry?: boolean };

    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;
      try {
        const refreshToken = localStorage.getItem("refresh_token");
        const response = await axios.post("/api/v1/auth/refresh", { refresh_token: refreshToken });
        const { access_token, refresh_token } = response.data;
        localStorage.setItem("access_token", access_token);
        localStorage.setItem("refresh_token", refresh_token);
        originalRequest.headers!.Authorization = `Bearer ${access_token}`;
        return api(originalRequest);
      } catch (refreshError) {
        localStorage.clear();
        window.location.href = "/login";
        return Promise.reject(refreshError);
      }
    }
    message.error((error.response?.data as any)?.detail || error.message || "请求失败");
    return Promise.reject(error);
  }
);

export default api;
```

```typescript
import { create } from "zustand";
import { persist } from "zustand/middleware";

interface AuthState {
  user: User | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  login: (username: string, password: string) => Promise<void>;
  logout: () => void;
  fetchUser: () => Promise<void>;
}

export const useAuthStore = create<AuthState>()(
  persist(
    (set) => ({
      user: null,
      isAuthenticated: false,
      isLoading: false,

      login: async (username: string, password: string) => {
        set({ isLoading: true });
        try {
          const data = await authApi.login({ username, password });
          localStorage.setItem("access_token", data.access_token);
          localStorage.setItem("refresh_token", data.refresh_token);
          set({ isAuthenticated: true });
        } finally {
          set({ isLoading: false });
        }
      },

      logout: () => {
        localStorage.removeItem("access_token");
        localStorage.removeItem("refresh_token");
        set({ user: null, isAuthenticated: false });
      },

      fetchUser: async () => {
        try {
          const user = await authApi.getCurrentUser();
          set({ user, isAuthenticated: true });
        } catch {
          set({ user: null, isAuthenticated: false });
        }
      },
    }),
    {
      name: "auth-storage",
      partialize: (state) => ({ isAuthenticated: state.isAuthenticated }),
    }
  )
);
```

## 6 结论与展望

### 6.1 研究总结

本文设计并实现了一个多模态科学文献智能解析与知识图谱构建平台，主要工作总结如下：

（1）**系统架构设计**：采用前后端分离架构，基于FastAPI和React构建微服务系统，结合MySQL、Neo4j、Redis和MinIO实现多数据源存储。

（2）**文档解析模块**：实现了基于PyMuPDF和PDFPlumber的PDF解析服务，支持文本提取、表格提取和图像提取，采用Celery实现异步处理。

（3）**任务管理模块**：设计了支持暂停、恢复、终止和重试的任务管理机制，提高了任务执行的灵活性和可控性。

（4）**知识图谱模块**：基于Neo4j构建了科学文献知识图谱，支持实体关系存储和可视化展示。

（5）**GraphRAG问答**：设计了基于Neo4j和Qwen的GraphRAG问答系统，实现了从关键词提取、图谱检索到LLM生成的完整流程。

（6）**标注管理模块**：开发了人机协同标注界面，支持双栏对比视图、多级审核流程和版本管理。

### 6.2 不足之处

尽管系统已基本实现预定功能，但仍存在以下不足：

（1）**知识图谱高级能力部分缺失**：实体链接 ✅ 已实现（Wikidata/DBpedia + 消歧 + 同义词合并，可降级）、关系推理/图谱补全 ✅ 已实现（规则推理 + TransE 链路预测，可降级）、语义搜索 ✅ 已实现（分面搜索 + 搜索建议，纯 Python 零依赖，可插拔 ES）、Text-to-Cypher ✅ 已实现（规则模板翻译 + 只读校验，LLM 预留可降级）；图谱检索仍以 Neo4j 模糊查询 + GraphRAG 为主，趋势分析/异常检测尚未实现。

（2）**关系抽取与结构化导出缺口**：REBEL/OpenIE 关系抽取模型 ✅ 已实现（`rebel_service.py`，Babelscape/rebel-large seq2seq 关系分类，输出规范化 SCREAMING_SNAKE 三元组，可插拔降级，已接入 `extraction_service.py`）；JATS 结构化输出尚未集成；参考文献解析已通过规则 + 正则兜底实现（`reference_service.py`，输出 CSL-JSON/BibTeX，未集成 GROBID）。

（3）**系统优化部分完成**：主动学习采样策略（不确定性/多样性/QBC，见 `active_learning_service.py`）、标注一致性评估（Fleiss'/Cohen's Kappa、Krippendorff's Alpha，见 `annotation_agreement_service.py`）、数据/模型版本管理（DVC 数据版本/MLflow 实验追踪与模型注册/自动重训管道，见 `version_management_service.py`）与置信度校准与漂移检测（Temperature/Platt Scaling、ECE、PSI/KS/卡方告警，见 `calibration_drift_service.py`）已完成；监控告警、CI/CD流水线等尚未实现。

### 6.3 未来展望

针对上述不足，未来工作可以从以下方向展开：

（1）**AI模型集成**：集成LayoutLMv3版面分析模型、SciBERT NER模型、BGE-M3嵌入模型，提升解析和抽取精度。

（2）**向量检索增强**：引入FAISS/ChromaDB，实现向量检索和混合检索。

（3）**主动学习闭环工程化**：在已实现的采样策略（不确定性/多样性/QBC）、标注一致性评估（Fleiss'/Cohen's Kappa、Krippendorff's Alpha）、数据/模型版本管理（DVC/MLflow 实验追踪与模型注册/自动重训管道）与置信度校准与漂移检测（Temperature/Platt Scaling、ECE、PSI/KS/卡方告警）基础上，接入真实训练任务队列（Celery + MLflow 远程后端）与 A/B 测试部署。

（4）**模型微调**：使用领域标注数据对LLM进行LoRA微调，提升问答质量。

（5）**监控运维**：引入Prometheus和Grafana，实现系统监控和告警。
